# Astra Finance — Architecture Notes

## Projects

```
AstraFinance.App            WPF (net10.0-windows). Views, view models, themes, WPF services.
  └─ AstraFinance.Infrastructure  (net10.0) File system, logging, persistence. EF Core/SQLite from Phase 2.
       └─ AstraFinance.Core       (net10.0) Domain models, interfaces, business rules, localization resources.
AstraFinance.Tests          xUnit; references all three.
```

Rules: views never query data; view models depend on interfaces; business rules live in Core and are testable without WPF.

## Composition

`CompositionRoot.ConfigureServices` registers everything. `App.OnStartup`:

1. Acquire the single-instance mutex (second launch signals the first and exits).
2. Ensure `%LOCALAPPDATA%\AstraFinance` exists; build the DI container (validated on build).
3. Load preferences (first run → language from Windows display language).
4. Apply language, attach `LocalizationSource`, initialize `ThemeService`.
5. Show `MainWindow`, navigate to Dashboard.

## Navigation

`PageCatalog` (Core) defines the pages. `PageRegistry` maps `AppPage` → view-model factory. Modules not yet built use `UpcomingModuleViewModel`; each phase replaces its registration. `NavigationService` creates a new page view model per navigation (fresh data) and disposes the previous one. Views are resolved through DataTemplates in `Views/PageTemplates.xaml`.

Search results carry a `NavigationTarget(page, entityId?)` so later modules can open detail views.

## Theming

- `Tokens.xaml` — theme-independent tokens and text styles.
- `Colors.Light.xaml` / `Colors.Dark.xaml` — palette brushes (identical keys, test-enforced).
- Accent dictionary — generated by `ThemeService` from `AccentPalette` (Core), contrast-tested.
- All color references use `DynamicResource`, so switching theme/accent is instant.
- `ThemeService` inserts the color dictionary at index 0 and accent at index 1 of `Application.Resources.MergedDictionaries`.
- The native caption is tinted with `DwmSetWindowAttribute` (dark mode, caption/text/border color, rounded corners).

## Localization

`.resx` in Core (`Resources/Strings.resx` English neutral, `Strings.id.resx` Indonesian). In XAML: `{loc:Loc Key}` (live-updating binding). In code: `ILocalizationService.GetString/Format`. Add a key to **both** files; tests fail otherwise.

Language (UI text) is separate from regional formatting (currency/number/date), which will be configured in onboarding and stored in the database.

## Financial data model

- Money: `long` minor units of the base currency (IDR → whole Rupiah). `CurrencyInfo.MinorDigits` drives formatting and parsing; never float/double.
- `Transaction` covers Income, Expense and Transfer. A transfer is **one row** (`AccountId` = source, `DestinationAccountId`); its optional fee is a separate Expense with `ParentTransactionId`.
- `BalanceAdjustment` holds documented corrections (signed delta, reason, balance before).
- Balance = Opening + Income − Expense + Transfers In − Transfers Out + Adjustments (`BalanceCalculator`), aggregated in SQL by `BalanceQueries`.
- Soft delete (`IsDeleted`, `DeletedAtUtc`) + EF global query filters: deleted rows are invisible to balances, totals and budgets.
- Dates: `DateOnly` for financial dates (stored `yyyy-MM-dd`), UTC `DateTime` for audit timestamps.
- Constraints also live in the database (CHECKs, RESTRICT foreign keys, unique indexes).
- Bills: `Bill` holds the schedule (first due date + recurrence); `BillPayment` records how one occurrence was handled — paid (`TransactionId` → the Expense it created) or skipped (`TransactionId` null), unique per (bill, due date). The next due date is derived (first occurrence after the latest handled one); a payment whose Expense was deleted counts as unpaid.

## Database lifecycle

`DatabaseInitializer` runs before the main window: newer-version guard → verified safety copy (when migrating an existing file) → `Migrate` → `quick_check` → seed built-in categories. Services use `IDbContextFactory` (one short-lived context per operation) and wrap multi-row writes in a transaction. Connection pragmas: foreign keys, WAL, `synchronous=FULL`, busy timeout (journal mode only on writable connections).

```bash
dotnet tool restore
```

```bash
dotnet dotnet-ef migrations add <Name> --project src/AstraFinance.Infrastructure --startup-project src/AstraFinance.Infrastructure --output-dir Database/Migrations
```

## Preferences vs. database

UI-only preferences (language, theme, accent, sidebar) live in `preferences.json` because they're needed before the database is unlocked. Writes are atomic; unreadable files are set aside and reported. Everything financial goes in SQLite (Phase 2).

## Security & privacy notes

- Data lives under the user profile (`%LOCALAPPDATA%`), outside the install directory.
- Logs contain technical events only — never PINs, amounts, descriptions or balances.
- The PIN (Phase 3) is an access control, not database encryption; this limitation will be documented in the app and README.
- Reminders (Phase 7) are checked only while the app is unlocked. Windows notifications never include amounts. The first Windows notification registers the app's notification identity for the current user (`HKCU\Software\Classes\AppUserModelId\Aprotoos.AstraFinance`).

## Adding a module (pattern for later phases)

1. Core: entities/interfaces/services + tests.
2. Infrastructure: repositories/EF configuration + migration.
3. App: page view model + view; register in `CompositionRoot.CreatePageRegistry` and `PageTemplates.xaml`.
4. Register an `ISearchProvider` for the module's records.
5. Add strings to both `.resx` files.
